## A Ring Buffer You Can Explain Line by Line {#f08}

The last Foundations chapter puts everything together in the most important structure in this book: a bounded single-producer single-consumer (SPSC) ring buffer. The version here is deliberately the simplest correct one, small enough to explain every line, with two atomics and no clever tricks. Chapter 8 then takes the same idea and makes it many times faster, one measured step at a time.

### Representation

The ring owns `N` slots, all constructed when the ring is. Two indices describe its state: `write_`, the slot the producer fills next, and `read_`, the slot the consumer empties next. Only the producer ever writes `write_`, and only the consumer ever writes `read_`. That *single-writer* property is what makes the ring possible without a lock or a read-modify-write.

`write_ == read_` means empty. If the producer were allowed to fill every slot, `write_` would come back round to `read_` and a full ring would look empty. So one slot always stays unused: the ring is full when `(write_ + 1) % N == read_`, and its usable capacity is `N - 1`. (Chapter 8 removes the wasted slot with indices that never wrap; this version keeps indices in `[0, N)` to make each state easy to draw.)

Walk through `N = 4`. Start with `read_ = write_ = 0`: empty. Push A into slot 0 and publish `write_ = 1`; push B into slot 1, `write_ = 2`; push C into slot 2, `write_ = 3`. The next push computes `next = 0`, sees `read_ == 0`, and returns `false`: full, with three items in four slots. Pop A and publish `read_ = 1`; now the producer can write slot 3 and wrap `write_` to 0. Draw these states once on paper; most ring bugs are off-by-one mistakes that a drawing exposes.

### The code

```cpp
template <class T, std::size_t N>
class ModRing {
    static_assert(N >= 2);
    static_assert(std::is_nothrow_default_constructible_v<T> && std::is_nothrow_copy_assignable_v<T>);

public:
    static constexpr std::size_t capacity = N - 1;

    bool try_push(const T& v) noexcept {                      // producer only
        const auto w = write_.load(std::memory_order_relaxed);
        const auto next = (w + 1) % N;
        if (next == read_.load(std::memory_order_acquire)) return false;   // full
        slots_[w] = v;
        write_.store(next, std::memory_order_release);
        return true;
    }

    bool try_pop(T& out) noexcept {                           // consumer only
        const auto r = read_.load(std::memory_order_relaxed);
        if (r == write_.load(std::memory_order_acquire)) return false;     // empty
        out = slots_[r];
        read_.store((r + 1) % N, std::memory_order_release);
        return true;
    }

private:
    std::array<T, N> slots_{};
    alignas(64) std::atomic<std::size_t> write_{0};
    alignas(64) std::atomic<std::size_t> read_{0};
};
```

### Every line, justified

**The producer reads its own index relaxed.** Nobody else writes `write_`, so the producer always sees its own latest value; no ordering is needed.

**The producer reads the consumer's index with acquire.** This is the **reuse** edge from Chapter F7. The consumer's release store of `read_` comes after it copied the slot out; the producer's acquire load that sees the new `read_` therefore happens after that copy, so overwriting the slot cannot race with the consumer still reading it.

**On full, it returns false and touches nothing.** The caller still has the item and decides what to do: retry, drop and count, or report back-pressure. The ring does not choose a policy for it.

**It writes the slot, then releases the new `write_`.** This is the **publication** edge. The release store is the moment the item becomes visible; the slot write before it is guaranteed to be visible to a consumer whose acquire load reads the new index. Swapping the two lines would publish a slot before it is filled.

**The consumer mirrors all of this.** Relaxed on its own index, acquire on the producer's (publication), copy out, release its new index (reuse). `out` is untouched when `try_pop` fails; the caller must check the return value rather than assume `out` was cleared.

**Modulo, not a mask.** `% N` works for any `N`; Chapter 8 restricts `N` to powers of two so the wrap becomes a cheap bit mask, and measures the difference.

**`alignas(64)` keeps the two indices on different cache lines**, so the producer's stores to `write_` do not keep stealing the line that holds `read_` (false sharing, Chapter 2). 64 bytes is the line size of mainstream x86 CPUs; some ARM cores need 128, which is why the library uses a constant (`kFalseSharingRange`) rather than a literal.

### The limits, stated

The ring is correct only under its preconditions, and they are worth listing as part of the design:

- **Exactly one producer and one consumer.** A second producer is not a configuration change: the single-writer argument for `write_` and the exclusive ownership of the slot both disappear. Multi-producer queues are a different design (Chapter 9).
- **Payload operations cannot throw.** All slots are default-constructed up front and assigned with a `noexcept` copy, so a push cannot fail half-way and leave a slot half-written. Chapter 8's ring constructs elements in place and handles the general case.
- **No allocation after construction.** Nothing in `try_push` or `try_pop` can allocate, take a lock or make a system call. That is what makes the ring suitable for a critical path.
- **No end-of-stream.** The ring cannot be closed. A consumer that knows how many items to expect can stop after that many; a long-running pipeline needs an explicit end-of-stream marker or a separate close protocol, as the pipeline of Chapter 19 does.
- **Retrying is not lock-free.** Each call does a bounded amount of work (wait-free), but a producer that loops on `try_push` until it succeeds waits as long as the consumer does nothing.

### Summary

- One producer writes `write_`, one consumer writes `read_`: the single-writer property removes the need for locks and RMW operations.
- Empty is `write_ == read_`; full is `(write_ + 1) % N == read_`; capacity is `N - 1`.
- Acquire on the other side's index plus release on your own gives both edges: publication and reuse.
- State the preconditions (one producer, one consumer, non-throwing payload, no close) as part of the design.
